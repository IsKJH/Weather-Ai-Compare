AI강점약점 / 한계주목할 행동
Claudegit diff를 첫 단계로 활용해 변경 범위를 빠르게 파악. 2개 파일에 분산된 버그도 모두 탐지.프롬프트 요구사항인 빌드까지만 확인. 단위 테스트 자발적 실행 없음.V4에서 Repository 계층을 분리한 결과, 온도 버그가 별도 파일에 위치했음에도 누락 없이 발견.
Codex모든 파일을 체계적으로 읽고, 빌드 + 단위 테스트까지 자발적 검증. JAVA_HOME 문제를 우회 경로로 해결.접근 방식이 가장 철저하지만 상대적으로 더 많은 단계를 실행.프롬프트에 없던 testDebugUnitTest를 자체 실행 — "컴파일 성공"과 "기능 정확성"을 구분하는 엔지니어링 마인드셋.
Gemini코드 흐름 추적 능력이 뛰어나 모든 버그를 정적 분석만으로 발견.JAVA_HOME 문제에서 우회 경로 탐색 없이 포기. replace 도구 오류 1회 발생.빌드 검증 실패를 V5 단위 테스트로 교차 검증하는 방식으로 대체 — 완전히 포기하지는 않음.
V5 단위 테스트가 V6 디버깅에 미친 영향: Gemini는 빌드를 검증하지 못하자 V5에서 작성한 단위 테스트를 교차 검증 수단으로 활용했습니다. 단위 테스트는 "테스트를 통과시키는 단계(V5)"뿐 아니라 "이후 코드 변경이 올바른지 확인하는 안전망"으로도 기능했습니다. V4 → V5 → V6의 연결이 실제 개발 사이클과 동일한 패턴을 보여줍니다.
