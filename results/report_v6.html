실험 설계
각 AI는 자신이 V1~V4에 직접 작성한 코드를 디버깅합니다. 버그 유형은 동일하지만 각 AI의 아키텍처에 맞게 위치를 다르게 심었습니다.
아키텍처 영향
Claude는 V4에서 Repository를 분리했기 때문에 버그가 2개 파일에 분산됐습니다. Codex·Gemini는 1개 파일에 집중. Claude는 분산된 버그도 모두 발견했습니다.
진짜 차이
버그를 몇 개 찾았느냐(3/3 동일)가 아니라, 어떻게 찾았고 얼마나 철저히 검증했는가가 이번 단계의 핵심 비교 포인트입니다.

04

디버깅 접근 방식

AI 첫 번째 행동 진단 방법 검증
Claude git diff 즉시 실행 diff hunk를 의미 기준으로 해석 → 변경된 줄 직접 확인 assembleDebug 성공
Codex 모든 .kt 파일 읽기 전체 코드 이해 후 git diff로 의심 지점 좁히기 assembleDebug + testDebugUnitTest 자체 실행 · JAVA_HOME 직접 해결
Gemini WeatherViewModel.kt 직독 git diff 없이 코드 흐름만으로 이상 패턴 식별 ./gradlew 실패 → V5 단위 테스트로 교차 검증
⚠️
git diff를 쓰면 사실상 답이 보입니다. Claude는 첫 행동으로 git diff를 실행했습니다. diff는 무엇이 바뀌었는지를 직접 보여주므로 버그 위치를 즉시 파악할 수 있습니다. 실무에서 유효한 습관이지만, 순수 코드 독해력 측정에서는 Gemini(git 이력 없이 직독, 194초)가 더 진정성 있는 디버깅 능력을 보여줬습니다.
🏆
Codex는 프롬프트 범위를 스스로 넘었습니다. 요구사항은 "빌드 통과"였지만, V5에서 직접 작성한 단위 테스트가 있다는 것을 인지하고 testDebugUnitTest를 자체 실행했습니다. JAVA_HOME 문제도 Android Studio JBR 경로를 찾아 직접 해결했습니다.
